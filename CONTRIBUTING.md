# Contributing Guide / Гайд по разработке

## Рабочий процесс

### Веточная модель (Git Flow)

```
main (стабильная версия)
  └─ develop (основная разработка)
      ├─ feature/... (новые функции)
      └─ bugfix/... (исправления)
```

### Создание новой функции

1. **Создайте ветку от `develop`**

   ```bash
   git checkout develop
   git pull origin develop
   git checkout -b feature/название-функции
   ```

2. **Внесите изменения**

   ```bash
   # Ваши изменения...
   git add .
   git commit -m "feat: описание изменений"
   ```

3. **Отправьте в репозиторий**

   ```bash
   git push origin feature/название-функции
   ```

4. **Создайте Pull Request** на GitHub

### Исправление ошибок

```bash
git checkout develop
git checkout -b bugfix/описание-ошибки
# Внесите исправления
git add .
git commit -m "fix: описание исправления"
git push origin bugfix/описание-ошибки
# Создайте PR
```

## Стандарты кода

### Форматирование Python

Используйте **PEP 8**:

```bash
pip install autopep8
autopep8 --in-place --aggressive AdvancedLogViewer.py
```

Или **Black** для более агрессивного форматирования:

```bash
pip install black
black AdvancedLogViewer.py
```

### Проверка стиля

```bash
pip install flake8
flake8 AdvancedLogViewer.py
```

### Типизация (опционально)

```bash
pip install mypy
mypy AdvancedLogViewer.py
```

## Коммиты

### Формат сообщений коммитов

```
<тип>(<область>): <описание>

<тело (опционально)>

<футер (опционально)>
```

**Типы**:
- `feat` - новая функция
- `fix` - исправление ошибки
- `docs` - документация
- `style` - форматирование кода
- `refactor` - рефакторинг
- `perf` - оптимизация производительности
- `test` - добавление/изменение тестов
- `chore` - техническое обслуживание

**Примеры**:

```
feat(ui): добавить темный режим
fix(serial): исправить потерю данных при отключении
docs: обновить README с новыми функциями
style: переформатировать код по PEP 8
```

## Версионирование

Проект использует **Semantic Versioning** (MAJOR.MINOR.PATCH):

- **MAJOR** - несовместимые изменения
- **MINOR** - новые функции (совместимо)
- **PATCH** - исправления ошибок

Пример: `1.2.3`

### Обновление версии

1. Обновите версию в коде:

   ```python
   __version__ = "1.2.3"
   ```

2. Создайте тег в Git:

   ```bash
   git tag -a v1.2.3 -m "Release version 1.2.3"
   git push origin v1.2.3
   ```

## Тестирование

### Локальное тестирование

Перед отправкой в репозиторий проверьте:

```bash
# Проверка синтаксиса
python -m py_compile AdvancedLogViewer.py

# Проверка импортов
python -c "import AdvancedLogViewer"

# Сборка бинарника (если нужна)
pyinstaller AdvancedLogViewer.spec
```

### Функциональное тестирование

- [ ] Приложение запускается без ошибок
- [ ] Serial порт подключается/отключается корректно
- [ ] Логи отображаются в реальном времени
- [ ] Фильтры работают правильно
- [ ] Автоскроллинг функционирует
- [ ] Логи сохраняются в файлы
- [ ] Настройки сохраняются в `settings.ini`

## Pull Request Checklist

Перед отправкой PR убедитесь:

- [ ] Ветка создана от `develop`
- [ ] Код отформатирован (PEP 8 или Black)
- [ ] Нет ошибок линтера (flake8)
- [ ] Функция протестирована локально
- [ ] Сообщение коммита соответствует стандартам
- [ ] Обновлена документация (если нужно)
- [ ] Нет конфликтов с `develop`

### Шаблон описания PR

```markdown
## Описание
Краткое описание изменений

## Тип изменения
- [ ] Новая функция
- [ ] Исправление ошибки
- [ ] Улучшение документации
- [ ] Рефакторинг

## Как тестировать
Шаги для проверки функции

## Чек-лист
- [ ] Код протестирован
- [ ] Нет ошибок линтера
- [ ] Документация обновлена
```

## Отчеты об ошибках

### Создание Issue

1. Проверьте, что ошибка еще не зарегистрирована
2. Используйте шаблон:

```markdown
## Описание
Четкое описание проблемы

## Как воспроизвести
1. Шаг 1
2. Шаг 2
3. ...

## Ожидаемое поведение
Что должно происходить

## Текущее поведение
Что происходит на самом деле

## Среда
- OS: Linux/Windows
- Python версия: 3.9
- Версия приложения: 1.0.0
```
