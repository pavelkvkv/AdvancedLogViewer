# ТЗ — Advanced Log Viewer 2

**Версия:** 0.1-draft
**Язык реализации:** C++17, Qt 6 (системный)
**Платформа:** Linux x86_64
**Конфигурация:** frameless-окна, многооконный режим, профили

---

## 1. Обзор

Advanced Log Viewer 2 (ALV2) — настольное приложение для приёма, отображения, фильтрации и сохранения потоковых текстовых логов по UART или UDP. Замена однооконного Python-прототипа. Цель: высокая производительность при больших объёмах данных, гибкая конфигурация через профили, многооконный интерфейс без системных декораций.

---

## 2. Глоссарий

| Термин | Определение |
|--------|-------------|
| **Профиль** | Набор настроек: тип соединения, порты фоллбека, кодировка, список Log-окон с их параметрами, схема расположения окон |
| **Log-окно** | Окно отображения одного потока лога (определяется глобальным фильтром) |
| **LogStore** | Хранилище всех принятых строк для одного глобального фильтра; живёт независимо от открытости окна |
| **LogReceiver** | Компонент-поток приёма данных с устройства |
| **LogDistributor** | Компонент маршрутизации строк по LogStore-ам согласно глобальным фильтрам |
| **Глобальный фильтр** | Фильтр LogStore-а: строки, не прошедшие его, в данный LogStore не попадают |
| **Оконный фильтр** | Временный фильтр, применяемый поверх LogStore в конкретном Log-окне; не влияет на хранение |
| **WDT** | Watchdog Timer — компонент аварийного завершения |
| **ProfileManager** | Singleton управления профилями; отслеживает "несохранённые изменения" |
| **Тема** | Цветовая схема интерфейса (системная / тёмная / светлая) |

## 3. Жизненный цикл приложения

### 3.1 Запуск

1. Загрузить `Settings` из `~/.config/AdvancedLogViewer2/settings.json`.
2. Загрузить `ProfileManager` из `~/.config/AdvancedLogViewer2/profiles/`.
3. Применить тему и язык из `Settings`.
4. Открыть `SettingsWindow`.
5. `QApplication::setQuitOnLastWindowClosed(false)`.

### 3.2 Завершение

Приложение завершается, когда:
- закрыто последнее Log-окно (все `SettingsWindow`/диалоги не считаются), **или**
- WDT инициировал аварийное завершение, **или**
- нажат `Ctrl+Q` из любого окна.

Крестик или кнопка «Закрыть» Log-окна, нажатые с **Shift** или **Ctrl**, завершают приложение немедленно (`QApplication::quit()`).

### 3.3 Применение профиля

При нажатии «Применить» в `SettingsWindow`:
1. Остановить `LogReceiver` (если активен).
2. Сохранить несохранённые изменения текущего профиля (показать диалог, если есть).
3. Закрыть все Log-окна текущего сеанса (LogStore-ы **не** уничтожаются, если профиль тот же).
4. Запустить `LogReceiver` с параметрами нового профиля.
5. Открыть Log-окна согласно профилю; каждому назначить соответствующий LogStore.
6. Восстановить геометрию окон из профиля.
7. Закрыть `SettingsWindow`.

## 4. Профили

### 4.1 Структура профиля (JSON)

```
profiles/
  <name>.profile.json
```

Поля:

| Поле | Тип | Описание |
|------|-----|----------|
| `name` | string | Отображаемое имя |
| `connection.type` | `"uart"` \| `"udp"` | Тип соединения |
| `connection.primary_port` | string | Основной порт (`/dev/ttyACM0` или `"5000"`) |
| `connection.fallback_ports` | array\<string\> | Порты фоллбека в порядке приоритета |
| `connection.baudrate` | int | Начальный бодрейт (UART) |
| `connection.encoding` | `"utf8"` \| `"cp1251"` \| `"cp866"` | Кодировка входящего текста |
| `windows` | array\<WindowDef\> | Описания Log-окон |
| `layout` | object | Сохранённое расположение окон (см. §6.3) |

**WindowDef:**

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | string | Уникальный идентификатор внутри профиля |
| `title` | string | Заголовок окна |
| `global_filter` | string | Глобальный фильтр (§8) |
| `text_color` | string | CSS-цвет текста (`#RRGGBB`) |
| `header_color` | string | CSS-цвет верхней панели |
| `visible` | bool | Открывать ли при применении профиля |

### 4.2 Несохранённые изменения профиля

Изменение открытого набора окон, их параметров или схемы расположения создаёт «несохранённый профиль». `ProfileManager` отслеживает это состояние. В `SettingsWindow`:

- Рядом с именем активного профиля отображается маркер `●` при наличии изменений.
- Контекстное меню профиля в списке: **«Сохранить текущее состояние сюда»**.
- Кнопка **«Сохранить как новый профиль»** создаёт новый.

При закрытии `SettingsWindow` с несохранёнными изменениями — диалог подтверждения.

### 4.3 Быстрое управление окнами из профиля

В `SettingsWindow` → вкладка «Профиль» → секция «Окна»:

- Список `WindowDef`-ов с чекбоксом «открыто».
- Кнопка «+» добавляет новое окно (только название и фильтр обязательны, цвет — дефолтный).
- Кнопка «Открыть» в строке открывает окно немедленно, даже во время активного сеанса. Окно подгружает накопленные данные из своего LogStore (§5.2).

## 5. Архитектура данных

### 5.1 Поток данных

```
LogReceiver (поток) → LogDistributor → [LogStore_1, LogStore_2, ...]
                                              ↓
                                       LogWindow (QListView → FilteredViewModel → LogStore)
                                              ↓
                                       LogFileWriter
```

### 5.2 LogStore

- Хранит все строки, прошедшие через глобальный фильтр.
- Внутреннее хранилище: `std::deque<LogChunk>`, где `LogChunk` = `std::vector<QString>` фиксированного размера (4 096 строк).
- Счётчик строк: `std::atomic<size_t>`.
- Живёт до явного уничтожения (`ProfileManager` решает, когда).
- Ограничение по числу строк: настраивается в `Settings` (по умолчанию 5 000 000; при достижении — вытесняются старые чанки).
- Thread-safety: RWLock (`QReadWriteLock`). Запись — из `LogDistributor`, чтение — из UI и `FilterWorker`.
- Сигнал `linesAppended(size_t from, size_t count)` — испускается в `LogDistributor`-потоке.

### 5.3 LogDistributor

- `QObject`-синглтон в главном потоке (или отдельном worker-потоке с `QEventLoop`).
- Получает от `LogReceiver` строку через thread-safe очередь.
- Для каждого `LogStore` проверяет глобальный фильтр: если строка проходит — добавляет. Несколько `LogStore`-ов могут принять одну строку.
- `LogDistributor` не владеет `LogStore`-ами, работает со списком зарегистрированных.

### 5.4 LogFileWriter

- Отдельный поток, привязан к `LogStore`.
- При получении сигнала `linesAppended` дозаписывает строки в файл `~/AdvancedLogViewer2_logs/<datetime>_<safename>.log`.
- `<safename>` — глобальный фильтр с заменой недопустимых символов (`/\:*?"<>|`) на `_`.
- Путь к директории настраивается в `Settings`.
- Буфер записи: сбрасывается по таймеру (500 мс) или при накоплении 256 КБ.

## 6. Пользовательский интерфейс

### 6.1 Log-окно

**Тип:** `QWidget` с `Qt::FramelessWindowHint | Qt::Window`.
**Минимальный размер:** 320×200 px.
**Перемещение:** drag за верхнюю панель.
**Ресайз:** обработчик событий мыши по краям (8 зон), курсор меняется.

#### Верхняя панель

Фиксированная высота 28 px. Цвет фона — `header_color` из `WindowDef` профиля.

| Элемент | Позиция | Описание |
|---------|---------|----------|
| **Иконка-заголовок** | левый край | 16×16 px + текст title, drag-область |
| **Автопрокрутка** | центр слева | Две иконки toggle: «scroll-to-end» (вкл.) / «scroll-locked» (выкл.); tooltip «Автопрокрутка» |
| **Свернуть** | правый край −2 | Иконка `−` |
| **Окно параметров** | правый край −1 | Иконка шестерёнки |
| **Закрыть** | правый край | Иконка `✕` |

**Поле фильтра окна:** появляется анимированно (высота 0→24 px за 120 мс) при наведении курсора на верхнюю панель; исчезает при уводе курсора за пределы панели **и** поля фильтра. Ввод + Enter применяет фильтр. Очистка + Enter снимает фильтр. Рядом — индикатор «фильтр активен» (цветная точка).

#### Текстовая область

- **Виджет:** `QListView` в режиме `SingleSelection` с пользовательским `QAbstractListModel` (`LogViewModel`).
- **Делегат:** `QStyledItemDelegate` — рисует строку с моноширинным шрифтом цвета `text_color`; фон чередуется (опционально).
- **Прокрутка:**
  - `Wheel` — вертикальная прокрутка (3 строки на тик);
  - `Ctrl+Wheel` — ускоренная (15 строк на тик);
  - `Shift+Wheel` — горизонтальная.
- **Автопрокрутка:** если включена и `LogViewModel` получил сигнал `linesAppended` — прокрутить в конец (только если пользователь не отскроллировал назад более чем на 3 строки).
- **Выделение и копирование:** стандартное `QListView` выделение мышью; `Ctrl+C` копирует выделенные строки в буфер через `QApplication::clipboard()`.

### 6.2 LogViewModel

- Наследует `QAbstractListModel`.
- `rowCount()` возвращает:
  - Если фильтр **не** активен: `LogStore::lineCount()`.
  - Если фильтр активен: `FilterIndex::size()`.
- `data(index, Qt::DisplayRole)` читает строку из `LogStore` (по индексу из `FilterIndex` или напрямую).
- Слот `onLinesAppended(size_t from, size_t count)`: если фильтр не активен — `beginInsertRows / endInsertRows`; если активен — запрос перефильтрации новых строк в `FilterWorker`.

### 6.3 Режим «Развернуть» и сохранение расположения

Кнопка «Развернуть» (или горячая клавиша `F11`) в `SettingsWindow` / верхней панели Log-окна раскладывает все открытые Log-окна по сохранённой схеме:

- Схема = массив `{window_id, x, y, w, h}` для каждого экрана.
- «Запомнить текущее расположение» — кнопка в `SettingsWindow`, сохраняет текущие геометрии окон в профиль (создаёт несохранённое изменение).

### 6.4 SettingsWindow

**Тип:** `QDialog` (один экземпляр, `Qt::Window`). При попытке открыть второй — поднять существующий.

**Вкладки:**

#### Вкладка «Профиль»

- Список профилей (слева), кнопки: Создать / Дублировать / Удалить / Переименовать.

## 7. Приём логов

### 7.1 LogReceiver

Отдельный `QThread`. Запускается при применении профиля, останавливается явно.

**Протокол входящего сообщения** (совместимость с v1.3):

| Формат | Описание |
|--------|----------|
| Текстовый | `L (HH:MM:SS:mmm) текст\n` — `L` ∈ {D, I, W, E} |
| Бинарный | `0x1L` + `uint32_le` (мс) + `0x20` + `текст\n` — `L` ∈ {1..4} |
| Прочее | Направляется в первый LogStore как есть |

Декодирование выполняется согласно `connection.encoding` профиля.

### 7.2 UART-соединение

- `QSerialPort` в потоке `LogReceiver`.
- **Фоллбек по портам:** если за 5 секунд не получено ни одного байта — переключиться на следующий порт из `fallback_ports` (циклически).
- **Детекция сбоя бодрейта:** если за скользящее окно 200 строк более 50% символов не являются буквенными, цифровыми или пробельными (isLetterOrNumber/isSpace) — попробовать `baudrate * 0.95` и `baudrate * 1.05`, округлив до ближайшего стандартного (`QSerialPort::standardBaudRates()`). При успехе сохранить в профиль.
- **Ротация портов** и смена бодрейта логируются в системный лог приложения (отдельный `QPlainTextEdit` в `SettingsWindow` → вкладка «Диагностика»).

### 7.3 UDP-соединение

- `QUdpSocket`, bind на `0.0.0.0:<port>`.
- **Фоллбек по портам:** перебирать `fallback_ports`, если за 3 секунды нет валидных датаграмм (датаграмма валидна, если содержит хотя бы одну строку, совместимую с форматом §7.1).
- Поддержка нескольких датаграмм в одном UDP-пакете (разделены `\n`).

## 8. Движок фильтрации

### 8.1 Синтаксис фильтра

Одно выражение **или** список через `|` (OR). Регистронезависимо.

| Синтаксис | Описание |
|-----------|----------|
| `текст` | Contains (подстрока) |
| `*pat*` | Wildcard: `*` — любые символы, `?` — один символ; используется `QRegularExpression` |
| `startswith("X")` | Строка начинается с X |
| `endswith("X")` | Строка заканчивается на X |
| `contains("X")` | Алиас для `X` |
| `A \| B` | OR: строка подходит, если подходит A или B |

Примеры:
```
E: (*:*:      ← wildcard
startswith("W: ") | startswith("E: ")
*UART* | *SPI*
```

### 8.2 FilterEngine

- `class FilterEngine` — парсит строку фильтра в AST (`FilterNode`), компилирует в `QRegularExpression` или набор предикатов.
- `bool matches(const QString& line) const` — thread-safe (только чтение).
- Используется как глобальным фильтром (`LogDistributor`), так и оконным фильтром (`FilterWorker`).

### 8.3 FilterWorker

- `QObject` в отдельном `QThreadPool`-потоке.
- Вход: `LogStore*`, строка фильтра.
- Выход: `FilterIndex` = `QVector<size_t>` (индексы строк в `LogStore`, прошедших фильтр).
- Алгоритм: итерирует по LogStore с read-lock, обновляет индекс блоками по 10 000 строк, между блоками проверяет флаг отмены.
- `LogViewModel` держит текущий `FilterIndex`; при смене фильтра — создаёт новый `FilterWorker`, старый отменяется.
- Прогресс отображается в Log-окне (indeterminate progress bar под верхней панелью, исчезает после завершения).
- Новые строки, поступающие во время активной фильтрации, добавляются в хвост индекса параллельно, если прошли фильтр.

## 9. Watchdog (WDT)

### 9.1 Архитектура

- `class WatchdogTimer : public QObject` — живёт в отдельном `QThread`, не использует `QEventLoop` (сырой цикл с `QMutex::tryLock`).
- Каждый «охраняемый» компонент регистрирует себя через `WDT::registerComponent(QString name, int maxIntervalMs)` → получает `WDT::Token`.
- Компонент вызывает `token.heartbeat()` (атомарная запись `std::atomic<int64_t>` — текущий `QDateTime::currentMSecsSinceEpoch()`).
- WDT-поток раз в 500 мс проверяет: `now - lastHeartbeat > maxIntervalMs` → завершение.

### 9.2 Мониторинг памяти

- Каждые 1 000 мс читать `/proc/self/status` → поле `VmRSS`.
- Считать скользящее среднее за 3 секунды.
- Если прирост > **10 МБ/с** в течение 3 последовательных измерений — аварийное завершение.
- Если `MemAvailable` (из `/proc/meminfo`) < 10% от `MemTotal` — аварийное завершение.

### 9.3 Аварийное завершение

```cpp
WDT::terminate(QString reason) {
    qCritical() << "WDT terminate:" << reason;
    // записать в ~/.config/AdvancedLogViewer2/crash.log
    std::_Exit(1);  // немедленно, без деструкторов
}
```

## 13. Интернационализация

## 14. Безопасность потоков — ключевые правила

1. `LogStore` защищён `QReadWriteLock`. Запись — только из `LogDistributor`-потока. Чтение — из любого.
2. `FilterWorker` читает `LogStore` с `QReadLocker`. Отмена через `std::atomic<bool>`.
3. `LogViewModel` модифицируется только в GUI-потоке. Сигналы из других потоков — только через `Qt::QueuedConnection`.
4. `WatchdogTimer::Token::heartbeat()` — только атомарная операция, без блокировок.
5. `ProfileManager` защищён `QMutex`; UI всегда обращается из главного потока.
6. `QLocalServer` (TestServer) — в отдельном потоке; взаимодействие с UI через `QMetaObject::invokeMethod`.
